# 离线网页保存：实机验证清单

本项目已在 Windows + Edge 的真实 CDP 上验证了完整链路（页面快照 → MHTML 转本地资源 → 离线服务读取）。Steam Deck 上的 CEF 仍需实机确认，按下面步骤执行即可。

## 准备

1. 构建并安装完整 ZIP（不要只替换 `dist`）：
   ```sh
   pnpm install --frozen-lockfile
   pnpm build
   python3 scripts/package.py
   ```
2. 在 Decky 中重新加载插件。
3. 设置页确认「扫码后自动离线保存」处于开启状态。

## 验证步骤

1. 打开 Portal 的「扫码传送」，用手机发送一个普通攻略网页（或小黑盒攻略页）。
2. 等待页面完全加载，弹出「已开始离线保存」提示。
3. 打开「本地文件」：
   - 顶部「离线网页」区域显示保存进度；
   - 普通网页完成后页数为 1；小黑盒类页面会显示「保存链接 i/n」，完成后页数为 1 + 已保存的文章链接数（最多 30）。
4. **关闭 Wi-Fi**（或开启飞行模式），点击该集合：
   - 文字、样式和图片应正常显示；
   - 对于小黑盒页面，点击正文里的一级文章链接应打开本地子页面，而不是联网地址；
   - 不应出现外网请求或空白占位。
5. 删除集合，确认整个目录（含 `pages/` 子页面和资源）一并删除。

## 失败时的判断

| 状态消息 | 含义 | 处理 |
| --- | --- | --- |
| 等待网页加载超时 | CEF 中没有匹配到该网址的页面 | 确认网页已在 Portal 中打开；同一网址只保留一个页面 |
| 无法唯一识别网页 | 存在多个同网址页面 | 关闭重复页面后重试 |
| 页面快照为空 / 浏览器响应超时 | `Page.captureSnapshot` 不可用 | 会自动退化为整页截图；若截图也失败，请记录状态消息 |
| 部分保存 | 部分资源未能写入 | 页面可打开，缺失的资源离线时不会加载 |
| 离线保存失败：… | 采集或写入异常 | 记录括号中的原始消息 |

## 已知限制

- 小黑盒类页面自动保存正文里的**一级**文章链接（最多 30 个）；子页面里的更深链接不递归，仍是联网地址。
- 保存链接期间阅读器会暂时隐藏，避免中间页面写入浏览历史；完成后恢复原页面。
- 链接页面的标题以打开后的页面为准；打不开或超时的链接会标记失败，不影响主页面和其它子页面。
- 脚本会被移除，视频不会下载；登录、收藏、播放等交互在离线状态不可用。
- 懒加载图片会先滚动页面到 30000px 以内触发加载；更长的页面可能仍缺少下方图片。
- 超长页面会按比例缩小成整页截图，文字可能变小。
